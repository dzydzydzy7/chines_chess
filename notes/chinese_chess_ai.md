# 学习笔记：中国象棋 AI 的实现思路

这份笔记关注可自己实现、可调试、可部署到 Jetson Orin Nano 的棋类 AI，不使用大语言模型直接生成走法。

## 1. 先理解：象棋 AI 在解决什么问题

给定当前局面、行棋方和必要的对局历史，AI 要输出一步合法且尽量好的走法：

```text
choose_move(position, history, time_limit) -> move
```

大多数非大模型方案都可以拆成两部分：

- **搜索（Search）**：向后推演“我走什么、对方怎么应、我再怎么走”。
- **评估（Evaluation）**：不能继续搜索时，给当前局面一个分数，判断对谁有利。

一个经典组合是：

```text
合法走子生成 + Alpha-Beta 搜索 + 局面评估函数
```

机器学习通常不是替代整个系统，而是替代或增强其中的某些部分，例如：

- 用神经网络代替手工局面评估函数。
- 用策略网络给走法排序，让搜索优先检查更有希望的走法。
- 用价值网络减少搜索深度。
- 通过自我对弈同时训练策略网络和价值网络。

## 2. 可选技术路线总览

| 路线 | 核心思想 | 优点 | 缺点 | 适合阶段 |
| --- | --- | --- | --- | --- |
| 随机/贪心 AI | 随机选子，或只选择当前得分最高的走法 | 极易实现，适合验证接口 | 棋力很弱，看不到后续威胁 | 第一个演示 |
| Minimax + Alpha-Beta | 搜索双方后续走法，用评估函数比较局面 | 稳定、可解释、无需训练数据 | 棋力依赖搜索效率和评估质量 | 最值得先掌握 |
| 手工评估 + 工程优化 | 加强搜索、排序、置换表、静态搜索等 | 棋力提升直接，工程含量高 | 调试和测试工作较多 | 主力版本 |
| 监督学习评估 | 用棋谱或引擎标注数据训练局面评分模型 | 能学习人类/引擎经验 | 依赖数据质量，仍通常需要搜索 | 有稳定传统 AI 后 |
| 策略网络 + 搜索 | 网络预测各走法概率，指导搜索 | 减少无效分支，更接近人类选点 | 模型和搜索整合复杂 | 进阶 |
| AlphaZero 式自我对弈 | 自我对弈产生数据，训练策略和价值网络，再用 MCTS 搜索 | 不依赖人类棋谱，上限高 | 训练成本高，系统复杂，难调试 | 研究型进阶 |
| 开局库/残局库 | 直接查询已知最佳或高质量走法 | 特定阶段又快又准 | 不能独立解决中盘 | 补强组件 |

**推荐主线：先把经典搜索 AI 做扎实，再尝试机器学习。** 这样即使模型效果不理想，也有可靠基线，而且能清楚判断模型究竟带来了多少提升。

## 3. 基础一：棋盘和走法的数据结构

AI 会反复执行和撤销走法，因此不能只考虑 UI 是否方便，还要考虑复制成本和搜索速度。

### 3.1 棋盘表示

最容易理解的是长度为 90 的一维数组：

```text
index = row * 9 + col
row: 0～9
col: 0～8
```

每个格子存储空位或棋子编码。棋子编码需要同时表达阵营和类型，例如：

```text
EMPTY
RED_KING, RED_ADVISOR, RED_ELEPHANT, RED_HORSE,
RED_ROOK, RED_CANNON, RED_PAWN
BLACK_KING, ...
```

UI 和 AI 应共用规则语义，但 AI 内部可以拥有自己的高性能结构。后续若需要更高性能，再研究位棋盘等表示，不必一开始过度优化。

### 3.2 局面不能只保存棋盘

至少还要保存：

- 当前行棋方。
- 上一步走法。
- 用于重复局面判断的历史信息。
- 可选：双方将/帅位置、当前子力评分等增量缓存。

### 3.3 走法表示

基础结构可以只有：

```text
Move {
    from: 起点,
    to: 终点,
    captured: 被吃棋子（可选缓存）
}
```

搜索时常见接口：

```text
generate_legal_moves(position) -> moves
make_move(position, move) -> undo_info
unmake_move(position, move, undo_info)
```

`make/unmake` 比每一步复制整个棋盘更高效，但实现错误也更隐蔽。必须测试“执行再撤销后，局面与原来完全一致”。

### 3.4 合法走法与伪合法走法

- **伪合法走法**：符合棋子自身移动方式，但可能让己方将/帅被攻击。
- **合法走法**：执行后不会使己方将/帅处于被攻击状态。

常见做法是先生成伪合法走法，再执行并检查己方王是否安全。这个基线容易验证，后续再优化。

## 4. 基础二：Minimax 与 Negamax

### 4.1 Minimax 的直觉

假设：

- 我方希望分数越高越好。
- 对方希望我方分数越低越好。
- 双方都做出对自己最有利的选择。

搜索树在不同层交替取最大值和最小值。到达最大深度后，用评估函数给叶子局面打分。

它的问题也很直接：中国象棋平均候选走法较多，若每个局面约搜索 40 个走法，深度 6 的原始节点规模就可能达到 `40^6`。因此必须剪枝和排序。

### 4.2 Negamax：更简洁的实现形式

零和双人对弈中，可以把评估统一为“**当前行棋方视角**”：

```text
negamax(position, depth):
    if depth == 0 or game_over(position):
        return evaluate_for_side_to_move(position)

    best = -INF
    for move in generate_legal_moves(position):
        undo = make_move(position, move)
        score = -negamax(position, depth - 1)
        unmake_move(position, move, undo)
        best = max(best, score)

    return best
```

关键是递归结果前面的负号：对手眼中的好局面，就是我方的坏局面。

### 4.3 终局分数与距离

将杀分数应远高于普通子力分数，并考虑将杀距离。例如：

```text
MATE_SCORE - ply    // 越快将杀越好
-MATE_SCORE + ply   // 越晚被将杀越好
```

这样 AI 才会优先选择更快的将杀，而不是认为所有将杀完全相同。

## 5. 基础三：Alpha-Beta 剪枝

Alpha-Beta 在不改变 Minimax 最终结果的前提下，跳过不可能影响根节点决策的分支。

- `alpha`：当前已能保证的最低分数。
- `beta`：对手允许我达到的最高分数。
- 当 `alpha >= beta` 时，无需继续搜索当前节点的其他分支。

```text
alpha_beta(position, depth, alpha, beta):
    if depth == 0:
        return quiescence(position, alpha, beta)

    for move in ordered_moves(position):
        make_move(position, move)
        score = -alpha_beta(position, depth - 1, -beta, -alpha)
        unmake_move(position, move)

        if score >= beta:
            return beta
        alpha = max(alpha, score)

    return alpha
```

这里暂时省略了终局、置换表和分数边界等细节。学习时应先写正确的小深度版本，再逐步加入优化。

**走法排序非常重要。** 如果好走法先被搜索，就能更早缩小窗口并触发剪枝。常见优先级：

1. 置换表记录的最佳走法。
2. 吃子走法，优先考虑“吃高价值子、低代价”的走法。
3. 杀手走法（killer moves）。
4. 历史启发分数高的走法。
5. 其他普通走法。

## 6. 基础四：手工局面评估函数

第一版可以从简单、可解释的特征开始：

```text
总分 = 子力分 + 位置分 + 机动性 + 王安全 + 其他结构特征
```

### 6.1 子力价值

先给每种棋子设置相对价值，例如兵、马、炮、车逐步增加，将/帅不参与普通子力交换计算。具体数值不是绝对真理，需要通过实战调整。

注意棋子价值会随阶段变化，例如兵过河后、残局时价值可能提高。

### 6.2 位置价值表（PST）

为不同棋子建立 90 格位置表。例如：

- 过河兵通常比未过河兵更有价值。
- 马在开阔位置通常比边角更灵活。
- 车占据开放线路可能更有优势。

评估红方和黑方时要注意坐标镜像，不能直接复用未翻转的表。

### 6.3 可逐步增加的特征

- 将/帅周围防护与暴露程度。
- 马腿是否容易受阻。
- 车、炮的线路与配合。
- 双方过河兵数量。
- 棋子机动性。
- 被攻击且缺乏保护的棋子。
- 开局、中局、残局采用不同权重。

特征越多不一定越强。每增加一组特征，都应通过固定测试集和大量对局确认，而不是只观察几盘棋。

## 7. 让传统 AI 真正变强：搜索工程

### 7.1 静态搜索（Quiescence Search）

固定深度搜索会在“刚吃完一个棋子”的边界停止，产生**水平线效应**：AI 误以为局面稳定，其实下一步就会被吃大子。

静态搜索在叶子节点继续搜索吃子、将军等剧烈变化，直到局面相对平静，再调用评估函数。这是从基础 AI 到实用 AI 的关键一步，同时要设置深度或节点保护，避免无限延伸。

### 7.2 迭代加深

先搜索深度 1，再搜索 2、3……直到时间耗尽：

- 随时保留上一层得到的最佳走法，超时时仍能返回。
- 浅层结果可用于下一层走法排序。
- 适合固定思考时间的 PVE。

### 7.3 置换表（Transposition Table）

不同走法顺序可能到达相同局面。用哈希键缓存：

- 搜索深度。
- 评估分数及其边界类型。
- 最佳走法。
- 必要时记录代际，用于替换旧数据。

常用 Zobrist Hash：给“格子 × 棋子”和行棋方分配随机数，走子时异或更新，避免每步重新计算整个棋盘。

置换表必须正确处理分数边界和将杀距离；否则可能出现很难复现的错误走法。

### 7.4 其他进阶优化

在基础版本稳定后，再逐项实验：

- 吃子排序：MVV-LVA 或静态交换评估。
- 杀手启发与历史启发。
- 空窗口搜索（PVS）。
- 空步裁剪、迟走法简化、Futility Pruning 等激进剪枝。
- 将军延伸、单应着延伸。
- 多线程搜索。

激进剪枝可能剪掉关键变化。每加入一种优化，都要比较节点数、耗时、战术题结果和实战棋力，不能只凭“搜索更快”判断有效。

## 8. 开局库与残局

### 8.1 开局库

从高质量棋谱提取常见开局，记录局面键、候选走法、权重或评分。AI 在命中时直接选择，或通过加权随机增加变化。

优点：

- 避免机器早期走出明显不合理的开局。
- 响应快。
- 可通过数据持续改进。

必须保留退出机制：离开开局库后正常交给搜索引擎。

### 8.2 残局

可以先为特定残局增加规则化知识，例如特定子力组合的基础策略。完整的残局数据库需要逆向枚举所有局面，生成和查询成本较高，可作为独立专题，不必阻塞初版。

## 9. 机器学习路线一：学习局面评估

这是最容易与传统搜索结合的机器学习方向：

```text
神经网络评估局面 + Alpha-Beta 搜索
```

### 9.1 输入表示

一种直观方案是把棋盘编码为多通道平面，例如 `14 × 10 × 9`：

- 14 个通道分别对应红黑双方 7 类棋子。
- 每个通道类似一张 10×9 的热图，有棋子的位置为 1，其余为 0。
- 可额外加入行棋方、历史局面等通道。

随后使用小型 CNN 提取空间特征，输出一个局面价值。输出可以是对数评分，也可以是当前行棋方胜率。

### 9.2 标签从哪里来

- 人类高手棋谱：容易获得对局结果，但中间局面的真实价值标签不明确。
- 强引擎标注：用传统引擎对采样局面深度搜索，把分数作为监督标签。
- 自我对弈：用最终结果或搜索评分训练，计算成本高。

工程上较实际的路径是：**先用传统 AI 生成标注数据，再训练小网络，最后把网络接回同一个搜索框架。**

### 9.3 必须避免的问题

- 随机按局面划分训练集和测试集，导致同一盘棋的相邻局面泄漏到两边。
- 只测网络均方误差，不测接入搜索后的真实棋力。
- 网络更大但推理太慢，导致搜索深度骤降，最终反而更弱。
- 把不同阵营视角的分值混在一起。

数据最好按完整对局划分，并统一“红方视角”或“当前行棋方视角”。

## 10. 机器学习路线二：策略网络与走法排序

策略网络学习：

```text
P(move | position)
```

输入为局面，输出为所有可能走法的概率分布。走法可以用 `from × to` 编码，最多有 `90 × 90 = 8100` 个起点终点组合，再过滤非法走法。

它有两种用法：

- **直接使用**：选择概率最高的合法走法。实现简单，但战术可靠性通常不足。
- **辅助搜索**：优先搜索高概率走法，减少 Alpha-Beta 分支或指导 MCTS。

训练标签来自高手棋谱中的实际走法，损失函数通常是交叉熵。一个实用实验是：保持搜索和评估不变，只比较“原排序”和“策略网络排序”的节点数、耗时与胜率，这样能明确模型价值。

## 11. 强化学习路线：MCTS 与 AlphaZero 式方法

### 11.1 MCTS 的基本过程

蒙特卡洛树搜索反复执行：

1. **选择**：沿树选择最值得探索的子节点。
2. **扩展**：增加一个或若干新节点。
3. **模拟/评估**：用随机模拟或价值网络估计局面价值。
4. **回传**：把结果更新到路径上的统计量。

纯随机模拟用于中国象棋通常效果有限，更常见的是策略价值网络引导的 MCTS。

### 11.2 AlphaZero 式闭环

```text
当前网络 + MCTS 自我对弈
        ↓
保存 (局面, MCTS 走法概率, 最终胜负)
        ↓
训练策略网络和价值网络
        ↓
新网络与旧网络对战，评估是否替换
        ↓
继续迭代
```

策略网络学习“更像 MCTS 选择走法”，价值网络学习“预测最终胜负”。

### 11.3 为什么不适合作为第一个 AI

- 自我对弈与训练需要大量计算。
- 数据生成、网络训练、模型评估互相耦合，问题定位困难。
- Jetson 适合部署小模型推理，不代表适合承担完整训练。
- 没有可靠规则引擎、快速走子生成和基线 AI 时，系统问题会被训练噪声掩盖。

更现实的做法是在开发机或外部 GPU 训练，Jetson 只负责推理和对局。

## 12. 难度设计不等于故意乱走

可选方式：

- 限制每步思考时间或最大深度。
- 限制节点数，使不同设备上的难度更稳定。
- 低难度缩小候选集合，但保留基本战术检查。
- 从评分接近的候选走法中按概率选择。
- 降低评估能力或减少开局库使用。

不要简单加入大量纯随机走法，否则体验更像程序出错。尤其要避免低难度 AI 漏掉非常直观的一步将杀或无故送将。

## 13. 工程接口建议

让 AI 与 UI、棋盘规则解耦：

```text
SearchLimits {
    max_depth,
    max_nodes,
    time_limit
}

SearchResult {
    best_move,
    score,
    completed_depth,
    nodes,
    elapsed_time,
    principal_variation
}

Engine {
    choose_move(position, history, limits) -> SearchResult
    stop()
}
```

AI 搜索应在独立任务或线程中运行，支持超时和停止。UI 不直接修改搜索中的棋盘；搜索结束后还要确认结果属于当前对局，防止重开或悔棋后旧结果落入新局面。

## 14. 测试与棋力评估

### 14.1 正确性测试

- 固定深度下，Alpha-Beta 与未剪枝 Minimax 的根节点评分一致。
- 执行/撤销走法后，棋盘、行棋方、历史与哈希完全恢复。
- 能识别一步将杀、必须应将、避免送将等基本战术。
- 超时、停止和连续多局不会返回旧走法或非法走法。

### 14.2 性能指标

- 每秒搜索节点数（NPS）。
- 达到的深度、总节点数、耗时。
- Alpha-Beta 剪枝效果。
- 置换表命中率。
- Jetson 上的内存、功耗和 P95 响应时间。

### 14.3 棋力评估

单盘胜负噪声很大。更可靠的方法：

- 建立战术题和残局测试集。
- 新旧版本进行多局对战，交换先后手。
- 使用相同时间或节点限制。
- 记录胜率、平局率及置信区间。
- 从多个不同开局开始，减少开局偏好影响。

任何新模型或优化都应与固定基线比较，保留版本、配置和对局记录。

## 15. Jetson Orin Nano 上的取舍

传统搜索通常更依赖 CPU 和内存访问；神经网络可以利用 GPU，但小模型也存在调用开销。

部署时重点考虑：

- 限制置换表大小，避免内存持续增长。
- 控制后台线程，避免 UI 和搜索争抢资源。
- 网络模型先在目标设备实测，再决定是否使用 TensorRT。
- 比较“网络评估带来的质量提升”和“搜索节点减少造成的损失”。
- 设置时间、节点和内存硬限制，确保每步都有可返回的结果。
- 训练尽量在外部机器完成，Jetson 专注推理。

## 16. 推荐学习和实现顺序

### 第 1 步：最小可用 AI

- 完成规则引擎和 `make/unmake`。
- 实现随机 AI、只按当前子力选择的贪心 AI。
- 打通 PVE、超时和走法合法性验证。

### 第 2 步：可解释的传统引擎

- 子力 + 位置表评估。
- Negamax。
- Alpha-Beta。
- 迭代加深和时间管理。

### 第 3 步：实用搜索优化

- 吃子优先排序。
- 静态搜索。
- Zobrist Hash 和置换表。
- 杀手走法、历史启发。
- 用测试证明每项优化的收益。

### 第 4 步：产品化补强

- 开局库、基础残局知识。
- 难度设置、搜索日志、复盘信息。
- Jetson 性能调优与长时间测试。

### 第 5 步：机器学习实验

先选一个变量做实验，不要同时重写整个引擎：

1. 用引擎标注局面，训练小型价值网络。
2. 接入相同搜索框架，与手工评估公平对战。
3. 若推理成本不划算，再尝试只训练策略网络辅助走法排序。
4. 最后才考虑自我对弈、MCTS 和完整 AlphaZero 式训练。

## 17. 最值得先做的实验

1. **深度实验**：固定评估函数，比较深度 1～5 的耗时、节点数和战术表现。
2. **排序实验**：比较随机顺序、吃子优先、置换表最佳走法优先的节点数。
3. **静态搜索实验**：观察它是否减少“交换到一半就停止”的明显误判。
4. **评估消融实验**：分别移除位置表、机动性、王安全，观察实战变化。
5. **学习评估实验**：用同一搜索框架比较手工评估与神经网络评估，而不是只比较模型离线误差。

这条路线能逐步得到一个真正属于自己的象棋引擎，同时保留足够的机器学习和深度学习扩展空间。
